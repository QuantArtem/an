# Тест-кейсы

Каждый кейс автоматизирован в `tests/e2e/test_scenarios.py` — имя функции начинается с номера кейса.
Запуск на поднятом стенде: `pytest tests/e2e -v`.

Общие предусловия: стенд запущен; используется партнёр с ключом `demo-partner-key`.

## TC-01. Основной сценарий: предоплаченный заказ

**Покрывает:** US-01, US-02, US-05, US-06, US-07 · UC-01, UC-02, UC-04 · BR-03, BR-05, BR-07, BR-12

| № | Действие | Ожидаемый результат |
|---|----------|---------------------|
| 1 | `POST /shipments`: постамат MSK-001, размер M, тип `PREPAID` | `202`; `status = CREATED`, `paymentStatus = NOT_REQUIRED` |
| 2 | Опрашивать `GET /shipments/{id}` | Статус становится `CELL_RESERVED`; заполнены `cellNumber` и `lockerAddress = «Москва, ул. Тверская, 7»` |
| 3 | `POST /lockers/{MSK-001}/deposits` с `shipmentId` | `201`; `cellNumber` совпадает с шагом 2, `cellSize = M` |
| 4 | Опрашивать отправление | Статус `READY_FOR_PICKUP`, заполнен `storageUntil` |
| 5 | `GET /notifications?shipmentId=` | Есть SMS по шаблону `READY_FOR_PICKUP` с 6-значным кодом |
| 6 | `POST /lockers/{MSK-001}/pickups` с кодом из SMS | `200`; в ответе `shipmentId` отправления |
| 7 | Опрашивать отправление | Статус `DELIVERED`; есть SMS по шаблону `DELIVERED` |
| 8 | `GET /shipments/{id}/history` | Последовательность: `CREATED → CELL_RESERVED → READY_FOR_PICKUP → DELIVERED` |

## TC-02. Оплата при получении

**Покрывает:** US-07, US-08, US-09 · UC-03, UC-04 · BR-09, BR-10, BR-11, BR-12 · NFR-12

| № | Действие | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Создать отправление `ON_PICKUP` на 149 900 коп., довести до `READY_FOR_PICKUP` | SMS содержит «К оплате 1499 руб.» и ссылку |
| 2 | `GET /tracking/{id}` | `amountDue = 149900` |
| 3 | Ввести верный код до оплаты | `409 PAYMENT_REQUIRED`, `Content-Type: application/problem+json` |
| 4 | `POST /payments` с ключом K | `201`; `status = PENDING`, `amount = 149900`, есть `paymentUrl` |
| 5 | Повторить `POST /payments` с ключом K | `200`; тот же `id` платежа |
| 6 | В psp-mock подтвердить оплату с флагом `duplicate` | PSP отправил webhook дважды, оба ответа `200` |
| 7 | Опрашивать отправление | `paymentStatus = PAID`; платёж `SUCCEEDED` |
| 8 | Проверить журнал уведомлений | Ровно **одно** SMS `PAYMENT_RECEIVED` |
| 9 | `POST /payments` с новым ключом | `409 ALREADY_PAID` |
| 10 | Повторять ввод кода | В течение нескольких секунд — `200`; отправление `DELIVERED` |
