# Каталог ошибок API

Все сервисы возвращают ошибки в едином формате **RFC 7807** (`Content-Type: application/problem+json`):

```json
{
  "type": "https://docs.lockerflow.example/errors/INVALID_SHIPMENT_STATE",
  "title": "Invalid shipment state",
  "status": 409,
  "code": "INVALID_SHIPMENT_STATE",
  "detail": "Отмена невозможна в статусе READY_FOR_PICKUP",
  "instance": "/api/v1/shipments/7b6f6f0e-2f55-4d6e-9d5c-3c1f8f1e2a10/cancel",
  "correlationId": "5f0c1a2e-7c0b-4a57-9d3e-0d4f7f1f8a11",
  "currentStatus": "READY_FOR_PICKUP"
}
```

| Поле | Назначение |
|------|------------|
| `code` | Машиночитаемый код. **Клиент строит логику только на нём**, а не на тексте `detail` |
| `detail` | Пояснение для человека; текст может меняться без смены версии API |
| `correlationId` | Передаётся в поддержку — по нему находятся все записи логов и события |
| дополнительные поля | Зависят от кода, перечислены в колонке «Доп. поля» |

Полнота каталога проверяется автотестом `tests/unit/test_contract_drift.py::test_error_codes_are_documented`:
код ошибки нельзя добавить в сервис, не описав его здесь.

## Сквозные

| HTTP | Код | Когда возникает | Доп. поля | Что делать клиенту |
|------|-----|-----------------|-----------|--------------------|
| 400 | `VALIDATION_ERROR` | Тело или параметры запроса не соответствуют схеме | `errors[]`: `field`, `message` | Исправить запрос. Повтор без изменений бессмыслен |
| 400 | `IDEMPOTENCY_KEY_REQUIRED` | Не передан заголовок `Idempotency-Key` | — | Сгенерировать UUID и передавать его при всех повторах запроса |
| 422 | `IDEMPOTENCY_KEY_REUSED` | Ключ уже использован с другим содержимым запроса | — | Ошибка в логике клиента: для нового запроса нужен новый ключ |

## shipment-service

| HTTP | Код | Когда возникает | Доп. поля | Что делать клиенту |
|------|-----|-----------------|-----------|--------------------|
| 401 | `UNAUTHORIZED` | Заголовок `X-API-Key` отсутствует или ключ неизвестен | — | Проверить ключ |
| 403 | `PARTNER_BLOCKED` | Партнёр заблокирован | — | Обратиться к менеджеру LockerFlow |
| 404 | `SHIPMENT_NOT_FOUND` | Отправления нет либо оно принадлежит другому партнёру | — | Проверить идентификатор |
| 409 | `DUPLICATE_EXTERNAL_ORDER` | У партнёра уже есть отправление с таким `externalOrderId` | `shipmentId` | Использовать существующее отправление |
| 409 | `INVALID_SHIPMENT_STATE` | Операция недопустима в текущем статусе | `currentStatus` | Запросить актуальное состояние и не повторять |

Причины отказа, которые приходят **не ошибкой, а статусом** `REJECTED` / `CANCELLED` в поле `statusReason`
(следствие асинхронного резервирования, ADR-0004):

| `statusReason` | Статус | Смысл | Что делать партнёру |
|----------------|--------|-------|---------------------|
| `NO_FREE_CELLS` | `REJECTED` | Нет свободной ячейки подходящего размера | Предложить покупателю другой постамат |
| `LOCKER_NOT_FOUND` | `REJECTED` | Постамата с таким идентификатором нет | Обновить справочник постаматов |
| `LOCKER_UNAVAILABLE` | `REJECTED` | Постамат не работает | Предложить другой постамат |
| `RESERVATION_EXPIRED` | `CANCELLED` | Посылку не привезли за 5 суток | Создать новое отправление |
| `STORAGE_EXPIRED` | `EXPIRED` | Получатель не забрал посылку за 72 часа | Ожидать возврата |

## locker-service

| HTTP | Код | Когда возникает | Доп. поля | Что делать клиенту (терминалу) |
|------|-----|-----------------|-----------|--------------------------------|
| 403 | `INVALID_PICKUP_CODE` | Код не соответствует ни одной посылке в постамате | `attemptsLeft` | Показать «Неверный код, осталось N попыток» |
| 404 | `LOCKER_NOT_FOUND` | Постамат не найден | — | Ошибка конфигурации терминала |
| 404 | `RESERVATION_NOT_FOUND` | У отправления нет резерва в этом постамате | — | Курьеру: посылка привезена не в тот постамат |
| 409 | `LOCKER_UNAVAILABLE` | Постамат не в статусе `ACTIVE` | — | Показать «Постамат временно не работает» |
| 409 | `INVALID_RESERVATION_STATE` | Закладка или изъятие недопустимы в текущем статусе резерва | `currentStatus` | Курьеру: вернуть посылку на склад / посылка уже обработана |
| 409 | `PAYMENT_REQUIRED` | Код верный, но заказ не оплачен | `shipmentId` | Показать QR-код со ссылкой на оплату; после оплаты повторять запрос с паузой 2 с |
| 429 | `PICKUP_BLOCKED` | Ввод кода заблокирован после 5 неверных попыток | `retryAfterSeconds`, заголовок `Retry-After` | Показать таймер и телефон поддержки |

## payment-service

| HTTP | Код | Когда возникает | Доп. поля | Что делать клиенту |
|------|-----|-----------------|-----------|--------------------|
| 401 | `INVALID_SIGNATURE` | Подпись webhook отсутствует или неверна | — | PSP: проверить секрет. Событие фиксируется как инцидент ИБ |
| 404 | `INVOICE_NOT_FOUND` | У отправления нет счёта (неизвестное или предоплаченное) | — | Проверить ссылку на оплату |
| 404 | `PAYMENT_NOT_FOUND` | Платёж не найден | — | Проверить идентификатор |
| 409 | `ALREADY_PAID` | Счёт уже оплачен | — | Показать «Заказ оплачен» |
| 409 | `INVOICE_CANCELLED` | Отправление отменено или срок хранения истёк | — | Показать «Оплата невозможна» |
| 422 | `AMOUNT_MISMATCH` | Сумма или валюта в webhook не совпадает с платежом | — | Разбор финансовой службой; автоматический повтор не поможет |
| 502 | `PSP_UNAVAILABLE` | Платёжный шлюз не ответил за 5 секунд или вернул ошибку | — | Повторить через несколько секунд **с тем же** `Idempotency-Key` |

## Какие ошибки можно повторять

| Класс | Примеры | Повтор |
|-------|---------|--------|
| Сетевой сбой, таймаут, `5xx` | `PSP_UNAVAILABLE`, обрыв соединения | Да, с тем же ключом идемпотентности и нарастающей паузой (1, 2, 4 с; не более 5 попыток) |
| `429` | `PICKUP_BLOCKED` | Да, после интервала из `Retry-After` |
| `409 PAYMENT_REQUIRED` | — | Да, пока идёт оплата: состояние меняется асинхронно |
| Остальные `4xx` | `VALIDATION_ERROR`, `INVALID_SHIPMENT_STATE` | Нет — результат не изменится |
