# Нефункциональные требования

Каждое требование измеримо: указаны метрика, целевое значение и способ проверки.
Колонка «Прототип» честно показывает, что реализовано в коде репозитория, а что зафиксировано
как требование к промышленной версии.

Обозначения: ✅ реализовано · 🟡 реализовано частично · 📐 только спроектировано.

## Производительность

| ID | Требование | Метрика и цель | Проверка | Прототип |
|----|------------|----------------|----------|----------|
| NFR-01 | Время ответа API создания отправления | p95 ≤ 300 мс, p99 ≤ 800 мс при 50 RPS | Нагрузочный тест | 📐 нагрузочное тестирование не проводилось |
| NFR-02 | Время ответа операций терминала (закладка, выдача) | p95 ≤ 500 мс | Нагрузочный тест | 📐 |
| NFR-03 | Задержка сквозной обработки «создание → ячейка зарезервирована» | p95 ≤ 5 с | Метрика `saga_duration` | 🟡 в e2e-тестах укладывается в секунды, метрика не собирается |
| NFR-04 | Задержка «оплата подтверждена PSP → ячейка открывается по коду» | p95 ≤ 5 с | Метрика | 🟡 аналогично |
| NFR-05 | Пропускная способность | 50 созданий/с устойчиво, 150/с пиково в течение 10 минут | Нагрузочный тест | 📐 |

|----|------------|----------------|----------|----------|
| NFR-06 | Доступность операций выдачи и закладки | 99,9 % в месяц (≤ 43 мин простоя) | SLO-мониторинг | 📐 один экземпляр каждого сервиса |

| NFR-09 | Недоступность PSP не блокирует создание, закладку и выдачу предоплаченных заказов | — | Тест отказа | ✅ PSP вызывается только при создании платежа |

| ID | Требование | Метрика и цель | Проверка | Прототип |
|----|------------|----------------|----------|----------|
| NFR-12 | Гарантия доставки событий — at-least-once; обработка — идемпотентная | 0 дублей побочных эффектов | TC-02 (дубль webhook), unit | ✅ |

| ID | Требование | Проверка | Прототип |
|----|------------|----------|----------|
