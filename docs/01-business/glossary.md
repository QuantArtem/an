# Глоссарий

Единый язык проекта (ubiquitous language). Термины из этой таблицы используются одинаково
в требованиях, API, событиях, схеме БД и коде.

| Термин | В коде / API | Определение |
|--------|--------------|-------------|
| Партнёр | `partner` | Интернет-магазин, подключённый к LockerFlow по API. Идентифицируется API-ключом |
| Отправление | `shipment` | Единица доставки: одна посылка одного заказа, направляемая в один постамат. Центральная сущность системы |
| Внешний номер заказа | `externalOrderId` | Номер заказа в системе партнёра. Уникален в рамках партнёра |
| Получатель | `recipient` | Физическое лицо, которое забирает посылку. В системе не регистрируется, идентифицируется телефоном |
| Постамат | `locker` | Автоматизированный терминал выдачи с набором ячеек, установленный по определённому адресу |
| Ячейка | `cell` | Запираемый отсек постамата размера S, M или L |
| Размер посылки | `parcelSize` | Габаритный класс посылки: S (до 15×35×45 см), M (до 30×35×45 см), L (до 45×35×60 см) |
| Резерв | `reservation` | Закрепление конкретной ячейки за отправлением с момента создания до выдачи или освобождения |
| Закладка | `deposit` | Операция помещения посылки курьером в зарезервированную ячейку |
| Выдача | `pickup` | Операция получения посылки получателем по коду |
| Изъятие (возврат) | `return` | Операция извлечения курьером невостребованной посылки для возврата партнёру |
| Код получения | `pickupCode` | Одноразовый 6-значный цифровой код, открывающий ячейку получателю |
| Срок хранения | `storageUntil` | Момент, до которого посылка ожидает получателя в ячейке (72 часа с закладки) |
| Оплата при получении | `ON_PICKUP` | Тип оплаты, при котором получатель оплачивает заказ онлайн перед открытием ячейки |
| Предоплата | `PREPAID` | Заказ оплачен магазину заранее, LockerFlow оплату не принимает |
| Счёт | `invoice` | Обязательство получателя оплатить отправление с типом `ON_PICKUP` |
| Платёж | `payment` | Попытка оплаты счёта через платёжный шлюз. По одному счёту может быть несколько попыток |
| PSP | `psp` | Payment Service Provider — внешний платёжный шлюз, на стороне которого вводятся карточные данные |
| Webhook | `webhook` | HTTP-уведомление, которое внешняя система (PSP) отправляет в LockerFlow о наступлении события |
| Событие | `event` | Факт, произошедший в сервисе и опубликованный в Kafka для других сервисов |
| Ключ идемпотентности | `Idempotency-Key` | Уникальный идентификатор запроса клиента: повтор запроса с тем же ключом не создаёт дубль |
| Correlation ID | `X-Correlation-Id` | Сквозной идентификатор, связывающий запрос, порождённые им события и записи в логах |
| DLQ | `lockerflow.dlq` | Dead Letter Queue — топик для событий, которые не удалось обработать после всех повторов |

## Статусы

Подробные диаграммы состояний — в [state-machines.md](../03-architecture/state-machines.md).

| Сущность | Статус | Смысл |
|----------|--------|-------|
| Отправление | `CREATED` | Принято от партнёра, ячейка ещё не подобрана |
| | `CELL_RESERVED` | Ячейка забронирована, ожидается курьер |
| | `READY_FOR_PICKUP` | Посылка в ячейке, код отправлен получателю |
| | `DELIVERED` | Получатель забрал посылку (финальный) |
| | `REJECTED` | Ячейку забронировать не удалось (финальный) |
| | `CANCELLED` | Отменено партнёром либо истёк резерв (финальный) |
| | `EXPIRED` | Срок хранения истёк, ожидается изъятие курьером |
| | `RETURNED` | Посылка изъята для возврата партнёру (финальный) |
| Оплата отправления | `NOT_REQUIRED` / `AWAITING` / `PAID` | Не требуется / ожидается / получена |
| Платёж | `PENDING` / `SUCCEEDED` / `FAILED` | Создан в PSP / успешно завершён / отклонён |
