# ADR-0007. Аутентификация участников

**Статус:** принято частично (в прототипе реализована только аутентификация партнёров) ·
**Затрагивает:** FR-02, NFR-17…NFR-23

## Контекст

К системе обращаются участники с разным уровнем доверия и разными техническими возможностями:
серверы партнёров, терминалы постаматов, браузер получателя, платёжный шлюз, операторы.

## Решение

| Участник | Механизм | Обоснование | Прототип |
|----------|----------|-------------|----------|
| Партнёр (сервер-сервер) | API-ключ в заголовке `X-API-Key`; в БД хранится SHA-256 ключа | Простая интеграция (BG-4); ключ длинный и случайный, поэтому быстрый хэш допустим | ✅ |
| Терминал постамата | mTLS: клиентский сертификат устройства, привязанный к `lockerId` | Устройство в недоверенной среде; сертификат можно отозвать точечно | 📐 |
| Курьер | OAuth 2.0 / OIDC, JWT с ролью `courier`; `courierId` берётся из токена, а не из тела запроса | Действия должны быть персонифицированы | 📐 в прототипе `courierId` передаётся в теле |
| Получатель на терминале | Одноразовый код получения (BR-07, BR-08) | Регистрация получателя не требуется | ✅ |
| Получатель на странице оплаты | Неугадываемый идентификатор отправления (UUID v4) в ссылке из SMS | Ссылка даёт право только оплатить — ущерб от утечки отсутствует | ✅ |
| PSP (webhook) | Подпись тела HMAC-SHA256 общим секретом + список разрешённых IP | Стандартная практика платёжных шлюзов | ✅ подпись, 📐 IP |
| Оператор | SSO компании, роль `support`; операции `/internal/*` доступны только из внутренней сети | Привилегированные действия | 📐 `/internal` не публикуется шлюзом, ролей нет |
| Сервис ↔ Kafka | SASL/SCRAM + ACL на топики: писать в топик может только его владелец | Защита от подмены событий | 📐 |

Проверка выполняется на двух уровнях: шлюз отсекает неаутентифицированные запросы и ограничивает
частоту (NFR-23); сервис проверяет права на конкретный объект — партнёр видит только свои
отправления, чужие возвращают `404`, а не `403`, чтобы не раскрывать факт существования.

## Последствия

- ➖ **Ограничение прототипа:** операции терминала (`/deposits`, `/pickups`, `/returns`) и чтение
  журнала уведомлений не аутентифицируются. Для стенда допустимо, для промышленной эксплуатации —
  блокирующий недостаток (см. [risks.md](../../07-delivery/risks.md), R-07).
- ➖ API-ключ не ротируется автоматически; процедура перевыпуска — в roadmap.
